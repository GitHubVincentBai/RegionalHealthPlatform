# 区域康养平台接口级详细设计

## 1. 文档说明

### 1.1 文档目标

本文档基于 [Arch.md](/Users/baizhiwen/MICROWARE/Git/RegionalHealthPlatform/docs/agents/Arch.md) 的总体架构设计，进一步细化一期系统的接口级设计，作为前后端联调、第三方接入、测试用例设计和接口评审的依据。

### 1.2 适用范围

本文档覆盖以下范围：

- Web 管理后台接口
- 护理/运营移动端接口
- 家属微信小程序接口
- IoT 设备接入接口
- 第三方平台回调接口

### 1.3 设计原则

- 统一通过 API Gateway 暴露业务接口
- 对外接口采用 REST 为主，设备与实时接口补充 MQTT/WebSocket
- 全部写接口默认要求鉴权、审计、幂等和错误码规范
- 同一领域接口命名统一、返回结构统一
- 对关键业务状态流转采用显式状态字段，不依赖隐式逻辑

## 2. 接口总体规范

### 2.1 接口域名与前缀建议

| 环境 | 域名示例 | 说明 |
|---|---|---|
| 开发环境 | `https://dev-api.regional-health.local` | 内部联调 |
| 测试环境 | `https://test-api.regional-health.local` | 集成测试 |
| 生产环境 | `https://api.regional-health.cn` | 正式服务 |

统一前缀建议：

- 管理后台接口：`/api/admin/v1`
- 移动工作端接口：`/api/mobile/v1`
- 家属端接口：`/api/family/v1`
- 设备接入接口：`/api/iot/v1`
- 第三方回调接口：`/api/open/v1`

### 2.2 通用请求头

| Header | 必填 | 说明 |
|---|---|---|
| `Authorization` | 是 | `Bearer <token>` |
| `X-Request-Id` | 是 | 请求唯一标识，用于日志追踪 |
| `X-Tenant-Code` | 否 | 一期可预留，默认单平台 |
| `X-Station-Id` | 否 | 当前站点上下文 |
| `X-Idempotency-Key` | 写接口建议 | 幂等键，防止重复提交 |
| `Content-Type` | 是 | `application/json` |

### 2.3 通用返回结构

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "requestId": "7f6d2a2a-6a6b-4e50-8df7-1f6d17a00123",
  "timestamp": "2026-04-05T15:30:00+08:00"
}
```

### 2.4 分页返回结构

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [],
    "pageNo": 1,
    "pageSize": 20,
    "total": 125
  },
  "requestId": "req_xxx",
  "timestamp": "2026-04-05T15:30:00+08:00"
}
```

### 2.5 通用错误码

| 错误码 | 含义 | 说明 |
|---|---|---|
| `0` | 成功 | 请求成功 |
| `40001` | 参数错误 | 请求参数缺失或格式错误 |
| `40003` | 幂等冲突 | 重复提交或幂等键冲突 |
| `40101` | 未登录 | Token 缺失或失效 |
| `40301` | 无权限 | 无功能权限或数据权限 |
| `40401` | 资源不存在 | 查询对象不存在 |
| `40901` | 状态冲突 | 当前状态不允许执行该操作 |
| `42901` | 请求频繁 | 限流触发 |
| `50001` | 系统异常 | 内部未处理异常 |
| `50021` | 第三方接口失败 | 外部依赖异常 |
| `50031` | 设备数据异常 | 设备上报数据格式错误 |

### 5.2 健康数据上报接口

| 项目 | 内容 |
|---|---|
| 接口名称 | 健康数据上报 |
| 请求方式 | `POST` |
| 路径 | `/api/iot/v1/health-data/report` |
| 鉴权 | 设备鉴权 |
| 幂等 | 是 |
| 调用方 | 穿戴设备网关、厂商平台 |

请求示例：

```json
{
  "eventId": "evt_202604051530001",
  "deviceCode": "HB10001",
  "deviceType": "bracelet",
  "elderId": "E0001",
  "metrics": {
    "heartRate": 76,
    "bloodPressureHigh": 132,
    "bloodPressureLow": 84,
    "bloodSugar": 6.1,
    "sleepDuration": 420
  },
  "measuredAt": "2026-04-05T15:29:00+08:00"
}
```

处理规则：

- 按 `eventId` 做幂等去重
- 对异常数值做范围校验
- 清洗后的数据写入时序存储
- 若命中阈值规则则生成健康预警事件

|---|---|---|
| `pending` | 待受理 | `accepted`, `expired`, `cancelled` |
| `accepted` | 已受理 | `arrived`, `cancelled` |
| `arrived` | 已到场 | `finished` |
| `finished` | 已完成 | 终态 |
| `expired` | 已超时升级 | `accepted`, `finished` |
| `cancelled` | 已取消 | 终态 |

### 14.2 告警事件状态

| 状态 | 含义 | 可流转到 |
|---|---|---|
| `new` | 新告警 | `assigned`, `ignored` |
| `assigned` | 已分派 | `processing`, `ignored` |
| `processing` | 处理中 | `resolved`, `false_positive` |
| `resolved` | 已处置 | 终态 |
| `false_positive` | 误报 | 终态 |
| `ignored` | 忽略 | 终态 |

## 15. 幂等、限流与审计要求

### 15.1 幂等要求

以下接口必须实现幂等：

- 健康数据上报
- 呼叫事件上报
- 设备注册
- 支付回调
- 告警回调
- 呼叫受理/完成

### 15.2 限流要求

- 登录接口按账号和 IP 限流
- 设备上报接口按设备编码限流和节流
- 家属查询接口按用户维度限流

### 15.3 审计要求

以下操作必须写审计日志：

- 登录与退出
- 老人档案新增、修改、注销
- 呼叫单人工受理与完成
- 告警事件人工处置
- 账单生成与缴费状态变更
- 权限变更与数据导出

## 16. 联调与验收建议

### 16.1 联调顺序建议

1. 认证与用户上下文
2. 老人档案与主数据
3. 健康数据采集与趋势查询
4. 呼叫链路与移动处置
5. 安防告警接入与处置
6. 家属查询与账单
7. 消息通知与支付回调

### 16.2 一期接口验收重点

- 核心接口成功率
- 写接口幂等有效性
- 状态流转正确性
- 权限控制正确性
- 回调接口抗重复和验签能力
- 实时推送延迟与稳定性
