# 功能页面字段集清单（基于“需求输入文档”）

## 1. 文档目的

本清单用于把原始需求文档中的业务功能，沉淀为可实现的“页面字段集”，用于产品、前后端、测试和数据建模对齐。

说明：
- 本文档的字段名采用工程友好的 `snake_case` 建议命名。
- 原始需求多为能力描述，未给出完整字段定义；本文在不改变原意前提下做了字段化落地。

#### Elder 入住首批 MVP 边界约束

适用范围：
- 长者基础档案创建、列表、详情
- 家属关系维护
- 入住基础信息记录
- 房间与床位关联
- 风险等级展示

本批允许落地的入住相关字段：
- `admission_id`
- `check_in_date`
- `check_in_status`
- `room_id`
- `bed_id`
- `notes`

本批仅保留扩展位、不进入首批字段模型的内容：
- 合同/签约：`agreement_status` 及任何合同编号、签署时间、签约流程字段
- 费用/押金：`deposit_amount` 及任何账单、收费、结算字段
- 护理计划：`care_level`、护理等级评估结果、护理任务编排字段
- 审批流：`approval_status`、`approval_by`、`approval_at`、`approval_comment`

约束说明：
- `check_in_status` 仅用于表达入住记录状态，不替代合同状态、收费状态或护理执行状态。
- `room_id` 与 `bed_id` 用于资源占用关联，不承载换床审批、押金冻结、费用计提等逻辑。
- 家属关系首批只支持联系人语义，不承载监护授权文件、支付责任人或护理决策链条。

## 6. 字段治理约束

- 统一主键：`elder_id`、`event_id`、`work_order_id`、`fee_order_id`。
- 全链路时间字段统一使用 `*_at`（ISO8601）。
- 风险与状态字段统一采用枚举字典，避免前后端自由文本。
- 家属端可见字段必须经过最小化脱敏（身份证、病史、定位历史）。
- 健康监测字段需保留采集来源（`device_id`）与审计轨迹。

## 7. 待确认项

- 入住审批是否一期强制（若不强制，A3 流程字段可降级为可选）。
- 补贴与余额是否由本平台结算，或仅做第三方结果回传。
- 家属端是否开放实时轨迹，或仅开放安全事件触发后的定位片段。
