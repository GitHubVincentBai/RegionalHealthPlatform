# Elder 入住首批 MVP 功能页面字段集清单

## 1. 文档目的

本清单用于给 `docs/product/Elder入住首批任务包.md` 提供稳定字段边界，供 `FrontAgent`、`PythonAgent`、`TestAgent` 按同一口径实施首批 MVP。

字段来源说明：
- 产品范围来源：`docs/product/Elder入住首批任务包.md`
- 架构映射来源：`docs/architecture/功能页面字段集清单.md`
- 数据与接口约束来源：`docs/architecture/接口级详细设计.md`、`docs/architecture/部署拓扑图与数据库设计文档.md`

## 2. 首批范围与排除项

首批纳入范围：
- 长者基础档案
- 家属关系
- 入住基础信息
- 房间与床位关联
- 风险等级
- 档案列表与档案详情入口

首批明确排除：
- 合同/签约工作流
- 费用、押金、账单、结算
- 护理计划、护理等级编排
- 审批流与审批意见

边界规则：
- `check_in_status` 只表达入住记录状态，不映射合同、收费、护理计划状态。
- `room_id`、`bed_id` 只表达床位占用关系，不携带费用、合同或审批语义。
- 家属关系只表达联系人关系，不扩展为支付责任、监护法律文件或护理授权链。

## 3. 跨页面复用字段

### 3.1 长者主档案

- `elder_id`
- `elder_code`
- `full_name`
- `gender`
- `birth_date`
- `age`
- `phone`
- `id_card`
- `station_id`
- `risk_level`
- `status`

说明：
- `birth_date` 为主存字段；`age` 可作为展示派生字段。
- `status` 用于档案服务状态展示，允许与 `check_in_status` 并存，二者不得混用。

### 3.2 家属关系

- `family_name`
- `relation_type`
- `phone`
- `is_primary_contact`

约束：
- 同一长者仅允许一个 `is_primary_contact = true`。
- 若后续需要通知优先级，新增字段应独立扩展，不替换主联系人语义。

### 3.3 入住与床位关联

- `admission_id`
- `check_in_date`
- `check_in_status`
- `room_id`
- `bed_id`
- `notes`

约束：
- 同一床位同一时刻仅允许一位在住老人。
- 本批不新增 `agreement_status`、`deposit_amount`、`care_level`、审批字段。

## 5. 回传给其他 Agent 的约束

给 `PythonAgent`：
- 首批模型只接受本清单字段；不得把合同、费用、护理计划字段塞入长者或入住基础模型。
- `check_in_status`、`status` 需要分开建模，避免一个字段承载两类状态。

给 `FrontAgent`：
- 页面表单与详情展示仅渲染本清单字段。
- 对未来扩展使用区块留白或占位文案，不增加未落地的伪字段。

给 `MasterAgent`：
- 后续若收到合同、费用、护理计划诉求，应拆成独立任务，不与当前 Elder 入住 MVP 合并验收。
