# 长者档案与入住首批任务包

## 目标

本任务包用于启动“长者档案 / 入住”这一批真实业务建设，供 MasterAgent 拆分后派发给 FrontAgent、PythonAgent、TestAgent，并在必要时由 ArchAgent 参与边界约束。

首批目标不是一次性做完整入住系统，而是先打通最小业务闭环：

- 创建长者档案
- 查询长者档案
- 记录入住基础信息
- 关联床位和家属关系
- 为后续合同、费用、护理计划预留扩展点

## 业务范围

结合现有产品与架构文档，首批纳入范围：

- 长者基础档案
- 家属关系
- 入住信息
- 房间与床位关联
- 风险等级
- 档案列表和档案详情入口

首批暂不纳入范围：

- 正式合同工作流
- 缴费与账单联动
- 护理计划编排
- 审批流
- 医疗机构深度接口对接

## 关键对象

### 长者档案

- elder_id
- elder_code
- full_name
- gender
- age 或 birth_date
- phone
- id_card
- risk_level
- status
- station_id

### 家属关系

- family_name
- relation_type
- phone
- is_primary_contact

### 入住信息

- check_in_date
- check_in_status
- room_id
- bed_id
- notes

## 首批任务拆分

### 任务 1：长者档案领域模型与 API

负责人：

- `PythonAgent`

建议交付：

- elder profile 领域模型扩展
- create/list/get API
- 入住字段与家属关系字段的最小模型
- 基本校验规则

验收标准：

- 支持创建长者档案
- 支持查询列表
- 支持查询详情
- 支持最小入住信息入参

### 任务 2：长者档案前端列表与详情骨架

负责人：

- `FrontAgent`

建议交付：

- 档案列表页
- 档案详情页
- 创建档案表单骨架
- 入住信息展示区块

验收标准：

- 页面具备列表、详情、创建入口
- 字段映射与状态展示清晰
- 能预留接入真实 API 的适配层

### 任务 3：测试矩阵与回归策略

负责人：

- `TestAgent`

建议交付：

- 长者档案创建用例
- 入住信息校验用例
- 家属关系字段校验用例
- 前后端基础冒烟路径

验收标准：

- 关键字段和状态流转有自动化测试覆盖
- 能明确列出未覆盖风险

### 任务 4：架构与数据约束校验

负责人：

- `ArchAgent`

建议交付：

- 长者、家属、入住、床位的边界约束
- 后续合同、费用、护理计划的扩展建议

验收标准：

- 首批模型不过度设计
- 能支撑后续二期扩展

## 推荐执行顺序

1. `ArchAgent` 明确首批字段边界
2. `PythonAgent` 完成后端最小 API
3. `FrontAgent` 完成列表、详情、创建页骨架
4. `TestAgent` 补齐测试矩阵和自动化验证
5. `MasterAgent` 做整合、验收和后续任务拆分

## 风险提示

- 入住信息和床位关系在一期容易被做成“只是几个字段”，后续会缺少状态流转能力
- 家属关系如果不预留主联系人和通知优先级，后续消息通知会返工
- 长者档案字段要从一开始考虑隐私与最小暴露
