# 区域康养平台产品原型文档 Prompt

你是资深养老行业产品负责人，请基于《沈阳市和平区全域综合养老服务项目（一期）信息化建设需求》输出一份可直接进入原型设计阶段的产品原型文档（PRD）。

## 一、项目背景

- 项目名称：沈阳市和平区全域综合养老服务项目（一期）
- 覆盖范围：1 处龙湖邻里中心养老服务点位 + 31 处社区居家养老服务点位
- 龙湖邻里中心建筑面积：约 12715.81 平方米
- 31 处社区点位建筑面积合计：约 19317.51 平方米
- 一期建设目标：
  - 实现老人健康数据实时监测与管理
  - 打造便捷的服务呼叫与响应系统
  - 构建智能化安全监控与预警机制
  - 优化养老运营管理流程
  - 促进老人、家属、工作人员之间互动交流

## 二、平台定位

平台名称暂定为“龙湖邻里中心数智养老服务平台”。平台需面向以下角色提供统一能力：

- 老人
- 老人家属/子女
- 护理员/医生/康复师/客服/站点工作人员
- 机构运营人员
- 管理部门/项目管理方

平台整体遵循“感知层 - 平台层 - 应用层 - 展示层”四层建设思路。

## 三、你要输出的 PRD 内容

请直接输出完整的 Markdown 文档，结构必须包含以下章节，并尽量写实、细化、可执行：

1. 产品概述
2. 建设目标与一期边界
3. 用户角色与使用场景
4. 业务流程总览
5. 产品信息架构
6. 终端矩阵与角色权限矩阵
7. 核心模块需求
8. 页面清单与页面原型说明
9. 关键流程原型说明
10. 数据指标与运营看板需求
11. 非功能需求
12. 项目范围、假设与风险

## 四、必须覆盖的核心模块

### 1. 基础档案中心

- 老人档案
- 家属档案
- 员工档案
- 机构/站点档案
- 房间/床位档案
- 设备档案

### 2. 健康管理系统

- 智能穿戴设备接入
- 心率、血压、血糖、睡眠等健康数据采集
- 健康趋势查看
- 健康预警
- 健康报告
- 医护干预记录

### 3. 服务呼叫系统

- 房间/公共区域一键呼叫
- 呼叫定位
- 呼叫分级
- 护理人员响应
- 处理闭环记录
- 超时预警与服务质检

### 4. 安全监控系统

- 视频监控接入
- 跌倒识别
- 异常聚集识别
- 外来人员闯入识别
- 门禁联动
- 告警处置闭环

### 5. 运营管理系统

- 人员管理
- 排班管理
- 考勤管理
- 绩效评估
- 财务管理
- 物资管理
- 餐饮管理
- 服务工单管理
- 数据报表

### 6. 社交互动平台

- 老人与家属视频通话
- 家属查看老人健康信息
- 家属查看护理记录
- 家属查看缴费情况
- 活动通知
- 健康知识发布
- 消息触达

## 五、页面原型说明要求

请为不同端输出页面清单，并对每个页面给出：

- 页面名称
- 使用角色
- 页面目标
- 核心组件
- 核心交互
- 关键字段
- 异常状态
- 与其他页面/模块的跳转关系

终端至少包括：

- Web 管理后台
- 护理/运营移动端
- 家属微信小程序
- 老人端简化交互界面（如适用）

## 六、流程设计要求

至少详细描述以下关键流程：

- 老人建档流程
- 智能设备绑定流程
- 健康数据上报与预警流程
- 紧急呼叫与响应处置流程
- 跌倒/异常事件告警处理流程
- 老人服务工单执行流程
- 家属查看健康信息与缴费流程

每个流程需包括：

- 触发条件
- 参与角色
- 前置条件
- 主流程
- 异常分支
- 结果状态

## 七、指标与验收要求

请给出一期建议重点指标，包括但不限于：

- 呼叫响应时长
- 呼叫闭环率
- 设备在线率
- 健康数据上传成功率
- 高风险老人预警处置及时率
- 护理任务完成率
- 家属活跃度
- 机构运营效率指标

并给出面向一期上线的验收口径建议。

## 八、文档输出风格要求

- 采用正式、专业、可落地的政府/养老项目文风
- 优先输出表格化、结构化内容
- 不写空泛概念，要落到页面、流程、字段、角色、指标
- 明确一期做什么，不做什么
- 对无法从原始需求明确获得的信息，使用“建议方案/待甲方确认”标注
